# Dependency Visualizer

CLI-инструмент для практической работы №2, **вариант 16, этапы 1–5**.
Программа читает TOML-конфигурацию, получает прямые зависимости NuGet и
строит граф транзитивных зависимостей рекурсивным обходом DFS, находит обратные зависимости и визуализирует граф через Graphviz.

## Реализованные этапы

### Этап 1 — минимальный прототип с конфигурацией

- Пользовательские параметры берутся из `config.toml`.
- Проверяются имя пакета, URL/путь репозитория, режим тестового репозитория,
  версия, имя SVG-файла и флаг ASCII-дерева.
- Сохранён CLI-запуск через `python -m dependency_visualizer`.

### Этап 2 — сбор данных NuGet

- Используется формат пакетов .NET (NuGet).
- Для точной версии корневого пакета загружается `.nuspec` через NuGet V3.
- Прямые зависимости извлекаются из XML стандартным `xml.etree.ElementTree`.
- Показываются диапазоны версий и целевые framework-группы.
- Для HTTP используется только стандартный `urllib`; менеджеры пакетов и
  сторонние библиотеки для получения зависимостей не используются.

### Этап 3 — построение графа зависимостей

- Граф строится **рекурсивным алгоритмом DFS**.
- Для каждой прямой зависимости загружаются её метаданные и рекурсивно
  анализируются следующие зависимости.
- Для NuGet-зависимости выбирается наибольшая опубликованная версия,
  удовлетворяющая указанному диапазону версий.
- Повторно встреченные узлы не раскрываются повторно.
- Циклические рёбра сохраняются в графе, но рекурсивный обход по ним
  прекращается; программа выводит список обнаруженных циклов.
- Реализован тестовый режим: вместо URL указывается JSON-файл графа,
  имена пакетов в котором состоят только из больших латинских букв `A-Z`.
- В тестовом режиме можно проверить ветвления, общие зависимости, конечные
  узлы и циклы без доступа к интернету.

### Этап 4 — обратные зависимости

- Добавлен режим `--reverse-dependencies [PACKAGE]`.
- Программа находит пакеты, у которых есть прямое ребро к указанному пакету,
  то есть пакеты, которые непосредственно зависят от него.
- Поиск выполняется рекурсивным DFS по графу, построенному на этапе 3.
- Уже посещённые вершины не обходятся повторно, поэтому циклы не приводят
  к бесконечной рекурсии.
- Если имя пакета не передано после параметра, используется `package_name`
  из TOML. Если пакет не входит в построенный граф, выводится понятная ошибка.
- Если обратных зависимостей нет, программа выводит пустой результат и число 0.

Примеры запуска на Windows из корня проекта:

```bat
set PYTHONPATH=src
python -m dependency_visualizer --config config.test.toml --reverse-dependencies D
python -m dependency_visualizer --config config.test.toml --reverse-dependencies E
python -m dependency_visualizer --config config.test.toml --reverse-dependencies
python -m dependency_visualizer --config config.test.no_reverse.toml --reverse-dependencies A
```

Для тестового графа из `stage3_graph.json`:
- у `D` обратные зависимости `B` и `C`;
- у `E` обратная зависимость `C`;
- у `A` обратная зависимость `D` (это ребро цикла).
- в отдельном ациклическом тестовом графе у корневого `A` обратных
  зависимостей нет (`config.test.no_reverse.toml`).

**Границы режима:** поиск выполняется среди вершин графа, который построен от
корневого пакета на этапе 3. Это не глобальный поиск по всему каталогу NuGet:
NuGet V3 не предоставляет готовый список всех пакетов, зависящих от заданного
пакета, в используемом здесь endpoint метаданных.

### Этап 5 — визуализация Graphviz

- По построенному графу создаётся текстовое описание на языке Graphviz DOT.
- DOT-описание всегда выводится в консоль.
- Утилита Graphviz `dot` преобразует DOT в SVG-файл с именем из `output_file`.
- Корневой пакет выделяется отдельной формой/цветом, версии указаны в подписях узлов.
- Циклические рёбра выделяются красным цветом.
- ASCII-дерево печатается только при `ascii_tree = true`; повторные узлы и циклы помечаются.
- В `examples/` лежат три SVG-примера для корневых пакетов `A`, `B` и `C` из тестового графа.

#### Установка Graphviz в Windows

Установите Graphviz для Windows с официального сайта https://graphviz.org/download/ и добавьте каталог `bin` (обычно `C:\Program Files\Graphviz\bin`) в переменную `PATH`. Проверьте установку в новом терминале:

```bat
dot -V
```

Python-зависимости устанавливать не нужно. Если `dot` не найден, приложение покажет понятную ошибку установки Graphviz.

#### Демонстрация для трёх пакетов

Из корня проекта выполните:

```bat
set PYTHONPATH=src
python -m dependency_visualizer --config config.test.A.toml
python -m dependency_visualizer --config config.test.B.toml
python -m dependency_visualizer --config config.test.C.toml
```

Команды создают `stage5_A.svg`, `stage5_B.svg` и `stage5_C.svg` в текущей папке. Готовые контрольные изображения также сохранены в `examples/`. Для тестового графа:

- `A`: зависимости `B`, `C`; транзитивно `D`, `E`; присутствует цикл `D -> A`.
- `B`: цепочка через `D`, далее цикл возвращается к `A` и `B`.
- `C`: ветви к `D` и `E`, общая ветвь `D` возвращается в цикл `A -> B -> D`.

#### Сравнение со штатными средствами NuGet

Для реального проекта сравнивайте состав транзитивных пакетов с выводом .NET SDK:

```bat
dotnet list package --include-transitive
```

Эта команда показывает прямые и транзитивные пакеты, но не строит ориентированную графовую диаграмму и не экспортирует SVG. Поэтому сравнивать следует состав/версии зависимостей, а не внешний вид. Возможные расхождения объясняются тем, что .NET SDK выполняет полноценное разрешение зависимостей с учётом `TargetFramework`, `RuntimeIdentifier`, центрального управления версиями, ограничений и уже восстановленного `project.assets.json`; текущая реализация строит граф по метаданным NuGet для одной выбранной версии и выбранным алгоритмом разрешения диапазона версий. Тестовые имена `A`, `B`, `C` предназначены только для проверки алгоритма и не являются пакетами NuGet.

- `config.py` — чтение и проверка TOML.
- `nuget.py` — HTTP-запросы к NuGet V3, разбор `.nuspec`, выбор версии
  зависимости из NuGet version index.
- `graph.py` — рекурсивный DFS, список смежности, обнаружение циклов,
  поиск обратных зависимостей и форматирование результатов.
- `test_repository.py` — чтение тестового графа из JSON.
- `visualization.py` — генерация Graphviz DOT, рендер SVG и ASCII-дерево.
- `cli.py` — связывает конфигурацию, загрузку метаданных и построение графа.
- `tests/` — автоматические тесты.
- `config.toml` — конфигурация реального NuGet-репозитория.
- `config.test.toml` — отдельная offline-конфигурация для этапа 3.
- `run.bat` — запуск на Windows.

## Требования и запуск на Windows

- Windows 10/11
- Python 3.11 или новее
- Интернет для реального NuGet-режима
- Устанавливать сторонние Python-пакеты не требуется

### Реальный NuGet-режим

Откройте `config.toml` и укажите пакет, версию и NuGet V3 service index:

```toml
package_name = "Newtonsoft.Json"
repository = "https://api.nuget.org/v3/index.json"
test_mode = false
package_version = "13.0.3"
output_file = "dependencies.svg"
ascii_tree = true
```

Запустите `run.bat`. Программа загрузит зависимости корневого пакета, затем
будет рекурсивно получать зависимости обнаруженных пакетов и строить граф.
Для каждой зависимости диапазон из `.nuspec` разрешается через список версий
NuGet: выбирается максимальная подходящая версия.

### Offline-демонстрация этапа 3

Чтобы проверить DFS и циклы без интернета:

1. Скопируйте содержимое `config.test.toml` в `config.toml` либо запустите:

```bat
set PYTHONPATH=src
python -m dependency_visualizer --config config.test.toml
```

2. В тестовом файле `tests/fixtures/stage3_graph.json` задан граф:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D", "E"],
  "D": ["A"],
  "E": []
}
```

Здесь `A` зависит от `B` и `C`; обе ветви имеют общую зависимость `D`;
`D` зависит от `A`, поэтому присутствует цикл `A -> B -> D -> A`;
`E` — конечный узел. Узлы должны называться только заглавными латинскими
буквами.

Ожидаемый результат содержит список смежности, DFS-дерево, версии/метки
узлов тестового графа и сообщение о цикле `D -> A`. Общий узел `D` раскрывается
только один раз.

## Формат вывода

В результате программа печатает:

1. Список смежности всего достижимого графа.
2. Дерево обхода DFS.
3. Список циклических рёбер, если они обнаружены.
4. Версию каждого узла (для тестового графа используется метка `test`).

Этап 5 сохраняет SVG в файл, указанный в `output_file`.

## Тесты

Из корня проекта:

```bat
set PYTHONPATH=src
python -m unittest discover -s tests -v
```

Тесты не требуют интернета. Проверяются TOML, разбор NuGet `.nuspec`, HTTP
последовательность с подменёнными ответами, рекурсивный DFS, общие зависимости,
циклы, обратные зависимости (несколько, одна, отсутствие, цикл), некорректные
имена тестовых пакетов и отсутствие корневого узла.

## Обработка ошибок

Выводится понятная ошибка при неверной конфигурации, недоступности NuGet,
отсутствии пакета/версии, некорректном JSON/XML, неподдерживаемом диапазоне
версий, повреждённом тестовом графе или отсутствии корневого пакета.
